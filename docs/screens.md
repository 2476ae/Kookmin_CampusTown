## S2 — 초기 화면 ❌

**언제** 사용자가 처음 들어왔을 때. 아직 아무 종목도 안 물어본 상태.

**왜 어려운가**
빈 채팅창만 덩그러니 있으면 초보자는 **뭘 쳐야 하는지 모릅니다.**
"테슬라 어때?"라고 쳐도 되는 건지, 티커를 정확히 써야 하는 건지, 한국어로 해도 되는지 모릅니다.
주식이 어려운 사람이 타겟인데 첫 화면에서 막히면 그걸로 끝입니다.
**이 화면이 진입 이탈률을 결정합니다.**

**정해야 할 것**
- 예시 질문 버튼을 둘 것인가 (`"애플 어때?"` `"요즘 반도체 주 어떤가요?"`)
- 인기 종목 / 최근 본 종목을 보여줄 것인가
- 검색창을 따로 둘 것인가 — 앞서 "대화 전체(입력도 우측에서)"로 정했지만, 초기 화면에서는 가운데가 비어 있어서 그 공간을 어떻게 쓸지가 미정
- 3분할을 유지할 것인가, 초기에는 1분할이었다가 답변 후 3분할로 펼칠 것인가

**담당 ③가 지금 할 것**
만들지 말고 **초안을 제안하세요.** 그림이든 글이든 상관없습니다.
주식 모르는 사람이 이 서비스를 처음 열었을 때 뭐가 보여야 안 막히는지,
그걸 판단할 수 있는 사람이 팀에 한 명뿐입니다.

## S3 — 생성 중 (로딩) ✅ 해소됨

**결정 (2026-09-20): API를 둘로 쪼갰습니다.**

```
GET /api/score?ticker=X     단순 JSON · 즉시
GET /api/opinion?ticker=X   SSE 스트리밍 · 10~30초
```

점수 엔진은 LLM을 안 쓰니 실측 **0.2ms** 입니다. 느린 건 LLM뿐입니다.
그래서 점수·순위·업종분포·근거를 먼저 보내고, 글만 그 위에서 흘러나오게 했습니다.
**30초 빈 화면이 아예 안 생깁니다.** 기다리는 동안 이미 볼 게 있으니 로딩 화면
설계 자체가 거의 필요 없어졌습니다.

SSE 이벤트 순서: `score` → `status` → `delta`(여러 번) → `opinion` → `done`
상장폐지 종목은 `score` → `done {skipped:"delisted"}` 로 끝납니다.

**언제** 질문을 보낸 직후부터 의견이 나오기 전까지.

**왜 어려운가**
LLM이 tool calling으로 DB를 여러 번 조회하고 야후에서 가격을 가져옵니다.
**10~30초가 걸립니다.** 초보자는 3초만 멈춰 있어도 고장 났다고 생각하고 나갑니다.

**정해야 할 것**
- 진행 단계를 보여줄 것인가 (`"재무제표 읽는 중…"` `"동종업계 58개와 비교 중…"`)
  - 장점: 기다릴 이유가 생기고, "그냥 지어낸 게 아니구나"라는 신뢰가 생김
  - 단점: 구현이 늘어남 (담당 ②가 스트리밍으로 진행상황을 내보내야 함)
- 아니면 스켈레톤(회색 뼈대)만 띄울 것인가 — 훨씬 간단하지만 신뢰 효과 없음
- 의견 문장을 한 글자씩 스트리밍할 것인가, 다 만들어지면 한 번에 띄울 것인가

## S4 — 종목을 못 찾음 ❌

**언제** 오타, 비상장 회사, 그리고 **한국 종목을 물었을 때.**

**왜 어려운가**
`"삼성전자 어때?"` 가 반드시 들어옵니다. 타겟이 한국인 초보자인데 우리는 미국 주식만 합니다.
여기서 `"종목을 찾을 수 없습니다"` 라고만 띄우면 사용자는 **우리 서비스가 고장 난 줄 압니다.**

한국 주식을 못 하는 건 우리 사정(상장폐지 데이터가 공개 API로 안 열림)이지
사용자 잘못이 아닙니다. 그걸 어떻게 말하느냐가 이 화면의 전부입니다.

**정해야 할 것**
- 한국 종목 요청을 따로 감지해서 다르게 안내할 것인가
- 오타면 추천을 띄울 것인가 (`"애플(AAPL)을 찾으셨나요?"`)
- 실패했을 때 다음에 뭘 하라고 할 것인가 (빈손으로 돌려보내지 않기)

## S5 — 데이터가 부족한 종목 ❌

**언제** 상장한 지 2년밖에 안 된 회사 → **매출 3년 CAGR을 계산할 수 없습니다.**
성장성 축이 통째로 비어버립니다.

**왜 어려운가 — 이건 UI 문제가 아니라 설계 구멍입니다**
점수는 4축 동일가중 평균인데, 한 축이 없으면:
- 3축만 평균 내면 → 축 가중치가 조용히 바뀝니다 (25%씩이 아니라 33%씩)
- 0점 처리하면 → 신규 상장사가 전부 최하위가 됩니다
- 점수를 아예 안 내면 → "이 종목은 판단 불가"라는 화면이 따로 필요합니다

**이건 계약에 영향을 줍니다.** `score.example.json` 에 "이 축은 계산 불가" 를 표현할
방법이 아직 없습니다. 담당 ②와 같이 정해야 합니다.

**담당 ②가 지금 할 것**
가짜 DB에 **일부러 데이터가 빠진 종목을 몇 개 넣어두세요.** 나중에 실데이터에서
터지는 것보다 지금 터지는 게 낫습니다.

## S6 — 상장폐지된 종목 ❌

**언제** Form 25가 접수된 종목을 물었을 때.

**왜 어려운가**
"최상단 빨간 배지"로 정했지만, 상장폐지된 종목은 **현재가가 없습니다.**
- 가격이 없으면 PER·PBR 계산 불가 → 밸류에이션 축 전체가 비어버림 (S5와 같은 문제)
- 최신 재무제표도 없을 수 있음 (공시 의무가 끝남)
- 그러면 점수를 내는 게 의미가 있는지 자체가 의문

**정해야 할 것**
- 점수 자체를 안 내고 경고 화면만 띄울 것인가 — 가장 정직하고 초보자 보호에 맞음
- 아니면 마지막 재무 기준으로 점수를 내되 "폐지 시점 기준"이라고 명시할 것인가
- 상장폐지 **직전**(Form 25 접수됐지만 아직 거래 중) 은 어떻게 다룰 것인가 — 가장 위험한 구간

**남은 기획 항목과 연결** — README의 "상장폐지 배지 판정 기준"이 이것입니다.

## S7 — 꼬리질문에 답할 때 ❌

**언제** 의견이 나온 뒤 우측 대화창에 `"왜 밸류에이션이 낮아?"` 를 쳤을 때.

**왜 어려운가**
화면 세 칸 중 **어디가 바뀌어야 하는지**가 안 정해져 있습니다.
- 우측에만 답이 쌓이면 → 가운데 의견과 따로 놀고, 좌측 근거와 연결이 끊김
- 가운데가 통째로 바뀌면 → 원래 의견이 사라져서 비교가 안 됨
- 좌측만 바뀌면 → 답변 문장이 어디에도 안 보임

**정해야 할 것**
- 꼬리질문 답변도 `evidence` ID를 달아서 좌측과 연동할 것인가 (연동하는 게 일관되지만 구현이 늘어남)
- 가운데 의견은 고정하고 우측만 쌓을 것인가
- 대화가 길어지면 처음 의견은 어떻게 되는가
