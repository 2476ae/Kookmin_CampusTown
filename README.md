# Kookmin_CampusTown

주식이 어려운 사람을 위한 미국 주식 종합의견 서비스.

종목 하나를 물으면 **점수 하나**와 **그 점수를 설명하는 글**이 나옵니다.
글의 모든 문장은 클릭하면 근거가 된 실제 수치로 펼쳐집니다.

> 상태: **기획 단계**. 코드 없음. 아래는 확정된 설계 결정과 검증된 데이터 소스입니다.

## 왜

주식 입문자가 종목 하나를 판단하려면 재무제표를 읽고, 동종업계와 비교하고,
거시 환경을 보고, 상장폐지 위험을 확인해야 합니다. 초보자는 이 중 어느 것도 못 합니다.

기존 서비스는 둘 중 하나입니다. 숫자만 던지거나(해석을 못 함),
결론만 던지거나(왜인지 모름). 이 프로젝트는 **결론과 근거를 같은 화면에** 놓습니다.

## 핵심 설계: 점수와 의견의 분리

| | 점수 | 의견 |
|---|---|---|
| 만드는 주체 | 계산 엔진 | LLM |
| 재료 | 재무 · 밸류에이션 · 모멘텀 | 점수 + 거시 + 차트 + 상폐 플래그 |
| 성질 | **결정적** — 같은 데이터면 항상 같은 숫자 | 생성 — 오늘의 시장 상황을 반영 |

LLM은 점수를 바꿀 수 없습니다. "어제 72점이었는데 오늘 65점"이 생기지 않습니다.
금융 서비스에서 재현 불가능한 숫자는 버그입니다.

### 점수는 절대평가가 아니라 업종 백분위

"72점"의 72가 어디서 왔는지 답할 수 없으면 점수를 믿을 이유가 없습니다.
가중치를 임의로 정하는 대신 **동종업계(SIC) 안에서의 백분위**로 환산합니다.

- "72점" → "동종업계 580개 중 상위 28%"
- 제가 정한 숫자가 아니라 데이터가 말하는 숫자입니다
- 반에서 몇 등인지는 초보자도 압니다
- 드릴다운했을 때 보여줄 것이 명확합니다 — 업종 분포 위에 찍힌 점

백분위는 **전종목 데이터가 있어야만** 계산됩니다. 시세 API를 긁어서는 못 만드는 화면입니다.

### 상장폐지와 거시는 점수 축이 아닙니다

- **상장폐지 위험** — "상폐 점수 2점"은 낮은 점수로 읽히지만 실제로는 *피해야 할 종목*이라는 뜻입니다. 점수가 아니라 화면 최상단 경고 배지.
- **거시(금리·CPI)** — 금리 하나 올랐다고 전 종목 점수가 동시에 내려가면 종목 비교 도구로서 쓸모가 없습니다. 거시는 점수의 *재료*가 아니라 점수를 *읽는 법*입니다.

## 데이터 소스

전부 직접 HTTP로 확인했습니다 (2026-09-20 기준).

| 소스 | 용도 | 상태 | 확인 내용 |
|---|---|---|---|
| **SEC `companyfacts.zip`** | 전종목 재무 팩트 | 사용 | 1,409,212,553 B · 일 단위 갱신. 종목별 크롤링 5,800회가 아니라 **다운로드 1회** |
| **SEC `form.idx` → Form 25** | 상장폐지 이벤트 | 사용 | Form 25 = Notification of Removal from Listing. **2026 Q2 한 분기 517건**. 인증 불필요 |
| **FRED API** | 거시 지표 | 사용 | 금리 · CPI · 실업률. 화면 상단 컨텍스트 전용 |
| **yfinance** | 실시간 가격 · 차트 | 사용 | 비공식 API. 짧은 캐시 필수 |
| ~~DART OpenAPI~~ | 국내 상장폐지 | **불가** | DS001 엔드포인트 4개 중 없음. 기업개황 17개 필드에도 상장상태 없음 (`corp_cls`는 Y/K/N/E 시장구분) |
| ~~KRX data.krx.co.kr~~ | 국내 상장폐지 | **불가** | 쿠키 세션 붙여도 `getJsonData.cmd` → `LOGOUT` |
| ~~data.go.kr KRX상장종목정보~~ | 국내 상장 목록 | **부적합** | 상장폐지일 없음. **제3자 재배포 금지** 조항 — 웹서비스 제공 시 약관 위반 |

국내 상장폐지 데이터가 공개 API로 열려 있지 않아 **미국 주식(NASDAQ + NYSE)만** 다룹니다.

### 알려진 함정

- Form 25에는 ETF 클래스 정리가 섞여 있습니다. "회사 상장폐지"만 거르는 필터 필요.
- XBRL 태그가 회사마다 제각각입니다 (`Revenues` vs `RevenueFromContractWithCustomerExcludingAssessedTax` 등). 정규화가 데이터 레이어 작업의 대부분입니다.
- `companyfacts.zip`은 1.4GB입니다. **저장소에 커밋하지 마세요** (`.gitignore` 처리됨).

## 구조

```
[데이터 레이어]  SQLite
  companyfacts.zip ──▶ 재무 팩트 · 전종목 · 전년도
  form.idx         ──▶ Form 25 상장폐지 이벤트
  FRED API         ──▶ 거시 시리즈
  yfinance         ──▶ 실시간 가격 (캐시)
          │
          ▼
[점수 엔진]  결정적 · LLM 안 씀
  지표 계산 → SIC 업종 내 백분위 → 종합 점수 1개
          │
          ▼
[LLM 오케스트레이터]  tool calling
  점수 + 거시 + 차트 + 상폐플래그 ──▶ 의견 문장
  문장마다 근거 ID를 부착  ← 좌측 드릴다운의 연결고리
          │
          ▼
[웹 UI]  3분할
  좌: 근거 드릴다운   중: 점수 + 의견   우: 대화
```

**문장마다 근거 ID를 붙이는 것**이 이 설계의 전부입니다.
없으면 좌측 사이드바는 숫자 덤프가 되고, 있으면 "이 문장 왜?" → 클릭 → 해당 수치로 점프가 됩니다.
