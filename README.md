# Kookmin_CampusTown

주식이 어려운 사람을 위한 미국 주식 종합의견 서비스.

종목 하나를 물으면 **점수 하나**와 **그 점수를 설명하는 글**이 나옵니다.
글의 모든 문장은 클릭하면 근거가 된 실제 수치로 펼쳐집니다.

> 상태: **부분 기획 완료.** 종합의견 결과 화면(S1)만 설계가 끝났고 나머지 화면은 미정입니다 — [docs/screens.md](docs/screens.md).
> 계약(`contracts/`)과 작업 분담([TASKS.md](TASKS.md))이 준비돼 있습니다.

## 왜

주식 입문자가 종목 하나를 판단하려면 재무제표를 읽고, 동종업계와 비교하고,
거시 환경을 보고, 상장폐지 위험을 확인해야 합니다. 초보자는 이 중 어느 것도 못 합니다.

기존 서비스는 둘 중 하나입니다. 숫자만 던지거나(해석을 못 함),
결론만 던지거나(왜인지 모름). 이 프로젝트는 **결론과 근거를 같은 화면에** 놓습니다.

## 핵심 설계: 점수와 의견의 분리

| | 점수 | 의견 |
|---|---|---|
| 만드는 주체 | 계산 엔진 | LLM |
| 재료 | 재무 · 밸류에이션 | 점수 + 거시 + 차트 + 상폐 플래그 |
| 성질 | **결정적** — 같은 데이터면 항상 같은 숫자 | 생성 — 오늘의 시장 상황을 반영 |

LLM은 점수를 바꿀 수 없습니다. "어제 56점이었는데 오늘 48점"이 생기지 않습니다.
금융 서비스에서 재현 불가능한 숫자는 버그입니다.

### 점수는 절대평가가 아니라 업종 백분위

"56점"의 56이 어디서 왔는지 답할 수 없으면 점수를 믿을 이유가 없습니다.
가중치를 임의로 정하는 대신 **동종업계(SIC) 안에서의 백분위**로 환산합니다.

- "56점" → "동종업계 58개 중 26위"
- 우리가 정한 숫자가 아니라 데이터가 말하는 숫자입니다
- 반에서 몇 등인지는 초보자도 압니다
- 드릴다운했을 때 보여줄 것이 명확합니다 — 업종 분포 위에 찍힌 점

백분위는 **전종목 데이터가 있어야만** 계산됩니다. 시세 API를 긁어서는 못 만드는 화면입니다.

### 상장폐지와 거시는 점수 축이 아닙니다

- **상장폐지 위험** — "상폐 점수 2점"은 낮은 점수로 읽히지만 실제로는 *피해야 할 종목*이라는 뜻입니다. 점수가 아니라 최상단 경고 배지.
- **거시(금리·CPI)** — 금리 하나 올랐다고 전 종목 점수가 동시에 내려가면 종목 비교 도구로서 쓸모가 없습니다. 거시는 점수의 *재료*가 아니라 점수를 *읽는 법*입니다.

## 점수 엔진

### 지표 8개 · 4축 · 축당 2개

| 축 | 지표 | 계산 | 방향 |
|---|---|---|---|
| **수익성** | 영업이익률 | `operating_income / revenue` | 높을수록 ↑ |
| | ROE | `net_income / equity` | 높을수록 ↑ |
| **성장성** | 매출 3년 CAGR | 연간 `revenue` | 높을수록 ↑ |
| | 영업이익 3년 CAGR | 연간 `operating_income` | 높을수록 ↑ |
| **안정성** | 부채비율 | `liabilities / equity` | **낮을수록 ↑** |
| | 영업CF/순이익 | `operating_cashflow / net_income` | 높을수록 ↑ |
| **밸류에이션** | PER | `market_cap / net_income` | **낮을수록 ↑** |
| | PBR | `market_cap / equity` | **낮을수록 ↑** |

**영업CF/순이익**은 이익은 흑자인데 현금이 안 들어오는 회사를 잡습니다. 초보자가 혼자서는 절대 못 보는 지표입니다.

### 모집단은 폴백 사다리

SIC 4자리는 표본이 3~4개뿐인 칸이 생기고, 2자리는 소프트웨어·광고·인력파견이 한 칸에 뭉쳐집니다.

```
SIC 4자리 → 유효표본 ≥ 30 ? 사용
  ↓ 부족
SIC 3자리 → ≥ 30 ? 사용
  ↓ 부족
SIC 2자리 → ≥ 30 ? 사용
  ↓ 부족
전체 시장
```

유효표본은 **지표마다 다릅니다.** 어느 단계를 썼는지 화면에 표시해야 합니다
("동종업계 58개" 와 "유사업종 1,200개"는 신뢰도가 다릅니다).

### 합치기는 축별 평균 → 축 평균 (동일가중)

```
종합점수 = (수익성 + 성장성 + 안정성 + 밸류에이션) / 4
```

지표 8개를 그냥 평균 내면 **안 됩니다.** 어느 축에 지표를 하나 더 넣는 순간 그 축이
자동으로 무거워집니다 — 숨은 가중치입니다. 축을 먼저 평균하면 "네 축을 똑같이 본다"는
한 문장으로 설명이 끝납니다. 가중치를 완전히 없앨 수는 없으니 가장 **설명 가능한** 형태를 고른 것입니다.

### 적자 기업

적자면 PER이 음수가 됩니다. 수학적으로는 "아주 싸다"로 읽히는데 실제로는 반대입니다.
**적자 기업의 PER·ROE 백분위는 0점 고정.** 결측 처리하면 "적자인데 종합점수 높음"이 나옵니다.

## 모멘텀은 점수에서 뺐습니다

20/60/110 이동평균으로 초기 모멘텀을 잡을 수 있는지 백테스트했습니다.
**대형주 50종목 · 10년(2016–2026) · 종목별 부호검정:**

```
초기 정배열 > 정배열 아님   :  14/50   p=1.000   ← 기각
전환 중(20>60, 60<110) > 하락 :  22/50   p=1.000   ← 기각

종목별 60일 선행수익률 중앙값:
  하락 (20≤60)           4.35%   ← 가장 높음
  전환 중                 2.74%
  정배열 초기 (0-10일)     2.98%
  정배열 성숙 (91일+)      0.83%   ← 가장 낮음
```

**이동평균이 위로 정렬될수록 이후 수익률이 낮았습니다.** 세 번 독립 테스트, 전부 같은 방향.
모멘텀을 점수에 넣으면 많이 오른 주식에 높은 점수가 붙고, 초보자가 그걸 보고 고점에 들어갑니다.

**대신 방향을 뒤집어 씁니다** — `성숙 0.83%`는 일관됩니다. 점수는 건드리지 않고
**"정배열 112일째 · 오래 오른 구간입니다"** 경고 배지로만 사용합니다.

> **이 결과를 과신하면 안 됩니다.** 대형주 50개 · 10년 살아남은 종목만(생존 편향) ·
> 거의 상승장이라 평균회귀가 유리했던 환경 · 거래비용 무시.
> "모멘텀은 없다"는 일반 명제가 아니라, *단일 종목 MA 배열 타이밍*이라는 특정 구현이 기각된 것입니다.

### 알려진 함정

실제 데이터로 확인한 것들입니다.

- **XBRL 태그가 회사마다 다릅니다.** Revenue 계열 태그 개수 — AAPL 8개, **TSLA 17개**, KO 5개. 우선순위 사다리 필요.
- **`Liabilities` 태그가 아예 없는 회사가 있습니다.** 코카콜라(KO)가 그렇습니다. `assets − equity` 역산 폴백 없이는 통째로 NULL이 됩니다.
- **세그먼트별 값이 같은 태그에 섞입니다.** 연결 전체 값만 골라야 합니다.
- **Form 25에 ETF 클래스 정리가 섞여 있습니다.** 회사 상장폐지만 거르는 필터 필요.
- **다운로드가 약 3GB입니다** (`companyfacts` + `submissions`). `.gitignore` 처리돼 있으니 커밋하지 마세요.

## 구조

```
[데이터 레이어]  SQLite
  companyfacts.zip ──▶ 재무 팩트 (정규화된 metric 7개)
  submissions.zip  ──▶ SIC 업종 · 거래소 · 티커
  form.idx         ──▶ Form 25 상장폐지 이벤트
  야후 chart API   ──▶ 가격 · 이동평균
  FRED API         ──▶ 거시 시리즈
          │  contracts/db_schema.sql
          ▼
[점수 엔진]  결정적 · LLM 안 씀
  지표 8개 → SIC 업종 내 백분위 → 축별 평균 → 종합 점수 1개
          │  contracts/score.example.json
          ▼
[LLM 오케스트레이터]  tool calling
  점수 + 거시 + 차트 + 상폐플래그 ──▶ 의견 문장
  문장마다 근거 ID 부착
          │  contracts/opinion.example.json
          ▼
[웹 UI]  3분할
  좌: 근거 드릴다운   중: 점수 + 의견   우: 대화
```

**문장마다 근거 ID를 붙이는 것**이 이 설계의 전부입니다.
없으면 좌측 사이드바는 숫자 덤프가 되고, 있으면 "이 문장 왜?" → 클릭 → 해당 수치로 점프가 됩니다.

## 돌려보기

```bash
python scoring/fake_db.py       # 가짜 DB 생성 (296종목, 예외 케이스 포함)
python scoring/test_engine.py   # 점수 엔진 검사 16개
python llm/test_opinion.py      # 의견 생성 + API 검사 10개
python scoring/check_db.py      # DB 가 계약을 지켰는지 (실DB 붙이기 전 필수)
python api/server.py            # http://localhost:8000
```

```
GET /api/score?ticker=35010     단순 JSON · 즉시 (실측 0.2ms)
GET /api/opinion?ticker=35010   SSE · score -> status -> delta -> opinion -> done
```

DB는 `data/` 에 둡니다 (통째로 `.gitignore`). `data/stocks.db` 가 있으면 그걸 쓰고,
없으면 `data/fake.db` 로 떨어집니다 — 담당 ①의 실DB가 들어오면 코드를 안 고쳐도
자동으로 붙습니다. `STOCKS_DB` 로 덮어쓸 수 있습니다.

API 키 없이도 전부 돌아갑니다 (의견은 목 데이터). 실제 LLM을 쓰려면:

```bash
cp .env.example .env               # 그 다음 .env 안에 키를 채워 넣으세요
pip install -U -r requirements.txt # -U 필수: 구버전 openai가 있으면 안 올라갑니다
```

`.env` 는 `.gitignore` 에 있습니다. 환경변수로 넣어도 되고(그쪽이 우선합니다),
`.env` 가 편하면 그걸 쓰세요.

### 모델

기본값은 **`gpt-5.6-luna`** 입니다. `.env` 의 `OPENAI_MODEL` 로 바꿀 수 있습니다.

| 모델 | 입력 $/1M | 출력 $/1M | 1건 |
|---|---|---|---|
| **gpt-5.6-luna** (기본) | 0.20 | 1.20 | **≈ 3.2원** |
| gpt-5-mini | 0.25 | 2.00 | ≈ 5원 |
| gpt-5.6-terra | 2.00 | 12.00 | ≈ 21원 |
| gpt-5.6-sol | 4.00 | 20.00 | ≈ 41원 |

호출 1건은 입력 약 3,500토큰 · 출력 약 1,300토큰입니다.
이 작업은 **이미 계산된 숫자를 평이한 한국어로 풀어쓰는 일**이라 최상위 모델이 필요 없습니다.
점수는 결정적으로 나와 있어서 모델이 하는 계산이 없습니다.
nano 급까지 내리는 건 권하지 않습니다 — 제품 가치의 절반이 용어 해설 문장입니다.
